# 第一阶段隔离验收与操作手册

本阶段保持单中心、MySQL、180 天保留、完整统计与提交后 ACK。100 台 Agent、100GB/天是待验证目标；1000GB/天仅探索容量拐点。执行前记录每台中心、数据库、生成器/Agent 主机的 CPU、内存、磁盘类型/容量、网络带宽/延迟、OS、JDK、MySQL 和源码版本。规格未知时不得输出容量承诺。

## 顺序与负载

1. 在相同规格的独立旧版和新版中心各初始化 V14。按 `tools/performance/README.md` 构建/启动真实 Agent，运行相同 seed、事件比例、基数、保留数据和查询参数。保存配置摘要与脱敏报告；限制原始目录访问，不提交 Token 或本地日志。
2. 冷启动和预热分别运行。正常负载使用 100 台、两个来源、100GB/天、7200 秒、10 名查询用户。分别执行 0.1%、1%、10% 错误率，大堆栈、高指纹和 URI 基数，另用 `--hot-source` 验证单来源 50% 热点。生成器落后或 Agent 退出，该轮无效。
3. 突发场景保持相同基础负载，10 倍输入持续 600 秒，然后恢复，观察至少 1800 秒。输入不随 ACK 减慢。配置磁盘队列足够容纳峰值，禁止靠丢弃事件通过。
4. 用 `--history-seed-mb` 预置与生产预期行数、事件比例和基数相同的 180 天日志，等待全部 ACK；记录数据库实际行数/存储字节。分别查询 24 小时、30 天、180 天并重复写入/查询场景。小体积跨日预置只验证时间语义。
5. 同负载比较清理开启和关闭的查询 P95。隔离数据中增加过期明细、AI、聚合、去重和批次；03:15 的任务固定 cutoff、每批独立提交。核对过期数据删除、保留数据和并发新事件完整，记录清理批数、行数与耗时。不要修改生产时间或保留天数来完成测试。
6. 以 100、300、1000GB/天逐级重复开放负载，记录输入/ACK 吞吐、在途批次、CPU、I/O、连接等待与队列斜率。出现持续积压时保存最后稳定点和瓶颈，后续级别停止，结论仅适用于记录的硬件。

## 通过条件

| 场景 | 必须满足 |
|---|---|
| 正常 | 最后 30 分钟队列无持续增长；产生到可查询 P95 ≤30 秒 |
| 突发 | 无队列溢出；恢复后 30 分钟内清除新增积压 |
| 查询竞争 | 总览、错误分组、日志流、详情常用查询 P95 ≤2 秒 |
| 清理竞争 | 清理完成且准确；查询 P95 增幅 ≤20% |
| 正确性 | `report.json` 的 counts_match、groups_match、producer_valid、agents_alive 全部为 true；check_failures/query_failures 为零 |

报告同时记录原始访问数、错误数、分组首次/最近时间、预期/实际次数。队列趋势由每 10 秒采样判断，不能只比较开头结尾；可见性探针数量不足时单独标注。统计必须包含超时/失败，不能只报告成功样本。默认生成器返回码只判正确性和生成器有效性，SLO 必须根据完整场景和样本独立判定。

## 故障与恢复矩阵

逐项在新建隔离环境执行，保存故障前后游标、批次 ID 和预期统计；这些信息只保存在受保护的本地目录。

| 故障 | 执行与核对 |
|---|---|
| 断网/429/503 | 断开测试网络或注入响应；指数退避并遵守 Retry-After，配置与心跳不被上传占锁；恢复后总数一致 |
| ACK 丢失/超时 | 在提交后丢弃响应或保持连接；批次保留、同 ID 重试、统计不重复，45 秒总截止释放在途 |
| 重启 | 分别终止 Agent 和中心，再保留 spool/游标启动；重建队列计数、继续发送，无遗漏和跳跃 |
| 满队列/磁盘错误 | 限制独立队列容量或撤销其写入权限；暂停读取，修复后校准恢复，禁止零占用假设 |
| 409/截断/轮转 | 制造偏移冲突、截断和轮转；同来源停发、在途结束后回退/切换代次，原批次顺序保持 |
| 删除/迁移 | 上传在途时删除或迁移来源；旧任务不得推进新来源游标，保留规则与原操作语义一致 |
| 数据库失败 | 注入唯一键冲突、死锁或断连；整批回滚，无成功 ACK；重试后计数准确 |

自动化覆盖列表见结果报告；表中未实际执行的外部故障不能标记通过。

## MySQL 回归与诊断

在可丢弃、已初始化 V14 的测试库设置受保护的 `MYSQL_IT_URL`、`MYSQL_IT_USER`、`MYSQL_IT_PASSWORD` 和 `MYSQL_IT_ISOLATED=true`，执行：

```bash
mvn -o -f backend/pom.xml -Dtest=MysqlBulkStorageIntegrationTest,MysqlRetentionIntegrationTest,MysqlErrorOccurrenceIntegrationTest test
```

默认 H2 测试：`mvn -o -f backend/pom.xml test`。Agent 用 JDK 8 执行 `mvn -o -f agent/pom.xml test`，前端在其目录执行 `npm test -- --run` 和 `npm run build`。回归会写测试数据，禁止指向生产库；不自动迁移测试库。

用 `mysql-observe.sql` 记录优化前后的 EXPLAIN ANALYZE、实际扫描行数、loops、慢语句 digest；同时采集连接池等待、CPU/I/O/GC。慢日志由测试环境管理员配置，不能将含原始参数的 SQL 导出到共享报告。当前不增加索引；需要索引时另附真实目标库执行计划和基数证据，单独提出迁移。

## 升级与回退

先升级中心，保持 `INGEST_MAX_INFLIGHT=4`，随后按 5、20、100 台升级 Agent，默认 `AGENT_UPLOAD_WORKERS=2`（1–4）。每一级核对统计、队列与资源后再扩展；统计差异立即停止，资源饱和先降低并发。上传过载返回 503 INGEST_BUSY 和 Retry-After: 1，不影响配置、心跳和查询准入。

回退使用上一版程序/发布包和运行参数，保留 spool、游标、来源配置；上传线程通过环境变量配置，不扩展本地 JSON 格式。正式发布记录保持 v1.0.0；本次仅源码与隔离测试，不部署生产，也不自动进入第二阶段。
