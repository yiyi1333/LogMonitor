# 第一阶段本地验证报告

日期：2026-09-30。最终源码版本 v1.0.9，正式发布仍为 v1.0.0。此报告区分功能回归、短时烟测和未执行的容量验收。

## 环境与限制

中心与生成器/真实 Agent 同机：macOS 26.6.2、arm64、8 个逻辑 CPU；中心 Corretto JDK 17.0.20，Agent Corretto JDK 8u504。根磁盘 460GiB、可用约 62GiB，底层介质与物理网络带宽未采集。宿主内存读取受沙箱限制，未填写估计值。网络使用 localhost，不能代表 100 台远程 Agent。

MySQL 8.4.11 使用 Docker Engine 28.3.0 的独立临时容器，V14 最终结构；Docker VM 8 CPU、8,218,316,800 字节内存，数据目录 tmpfs，默认 InnoDB 参数。该环境适合验证 SQL/事务，不能代表持久磁盘容量。其他本地任务共享主机，结果包含竞争干扰。

## 自动化验证

- Agent：21 项通过，涵盖连续读取、不同来源并发、同来源顺序、ACK 丢失重试、截断协调、来源删除、409 回退、重启恢复、队列统计失败及上传总截止时间。
- 原生 MySQL：6 项通过，涵盖 1101 条分块、唯一键失败整批回滚、两个来源共享指纹并发累加、历史首次/筛选统计、错误流和关联 AI 清理。数据库复用时测试命名空间隔离；保留测试使用已初始化签名，避免测试数据触发历史命名空间重算。
- H2 后端全套：67 项，60 项通过、7 项按环境条件跳过；前端 43 项通过，构建通过（Node 24.19.0）；外部模型请求测试缺少外部服务，默认跳过；原生 MySQL 测试默认未设置专用环境时跳过。

这组短时低负载结果体现上传调度改动可工作，不能证明性能收益或查询回退；没有足够样本和独立硬件进行统计推断。基线详情见 BASELINE.md。

## 原生 MySQL 端到端烟测

使用优化中间版 v1.0.7、2 台真实 Agent、4 个来源、2GB/天、20 秒、1 名查询用户。额外通过真实 Agent 预置 0.25MiB 匿名历史记录，覆盖约 179 天历史与当前日期，验证 180 天查询范围，不代表 180 天真实数据规模。

预期和实际：访问 6262、错误 74，分组次数及首次/最近时间全部一致。查询 P95 0.0874 秒；产生到可查 P95 1.1606 秒（2 个探针）；生成器最大调度延迟约 0.020 秒。运行期间存在测试清理竞争，但未采集稳定的无清理对照，不能判定清理竞争的 20% 门槛。

同一小数据集只读 EXPLAIN ANALYZE：

| 查询 | 实际扫描与耗时 |
|---|---|
| 原分组聚合形状 | 组主键扫描 76 行；发生记录 56 次查找、平均 1.32 行；输出聚合 37 组；约 2.41ms |
| 新窄字段聚合形状 | 组服务索引 56 行；发生记录同样 56 次、平均 1.32 行；聚合 37 组，最后查父组 20 次；约 0.584ms |
| 访问趋势 | 访问索引扫描 3223 行，筛选 1014 行；约 2.91ms |
| 错误流 | 时间索引扫描 4498 行，组主键查询 4463 次，输出 45 行；约 5.02ms |

这是代表性 SQL 形状的单次观测，不含所有筛选组合，不构成完整 API 的优化前后执行计划基线。错误流仍可能受历史行数和命名空间偏斜影响；本次未添加索引。查询计划和 digest 原始记录保存在本机临时目录，报告不导出凭证、正文或路径。

最终 v1.0.9 使用相同 MySQL 历史烟测参数复核：访问 6262、错误 74 和分组时间全部匹配，生成器及 Agent 状态有效；查询 P95 0.0858 秒，可见延迟 P95 2.0875 秒（2 个探针）。
